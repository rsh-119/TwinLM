# TwinLM documentation

TwinLM is a small, self-hosted, **OpenAI-compatible LLM gateway** that cuts AI spend. Your applications keep
using the OpenAI SDK (or LangChain, LlamaIndex, anything that speaks the OpenAI API). You change two lines,
`base_url` and `api_key`, and every request now goes through TwinLM, which:

- sends each use case to the **cheapest model that is good enough**, and falls back to another provider when one is down;
- answers **repeated requests from cache** for $0;
- **caps output tokens** so one bad prompt can't run up a bill;
- records **tokens and cost per app, team and model**, and reports **how much you saved** against the model you would otherwise use.

It runs on your own server or cloud. Prompts go only to the providers you configure, with your own provider keys.

## How it works

```text
Your apps (chatbot, support tool, scripts, agents)
   |  OpenAI-style requests, one TwinLM key per app
   v
TwinLM gateway
   auth and limits -> cache -> router (aliases, fallback,
   retries, breakers) -> provider -> usage and cost record
   |
   v
OpenAI, Gemini, Groq, DeepSeek, Mistral, Ollama, vLLM, ...
```

A request names a **model alias** such as `auto`, `fast` or `smart`. You decide in one config file,
[`gateway.toml`](/docs/config/), which real models sit behind each alias and in what order. Apps never
hard-code a provider, so you can switch to a cheaper model without redeploying anything.

## Honest limits

<Note title="Know before you deploy">
One gateway instance is the supported setup: rate limits, circuit breakers and the cache live in process memory.
The daily budget is advisory (concurrent requests can overshoot it); use your provider's spend limits as the hard
stop. Costs are estimates from the prices you configure. There is no SSO, no semantic cache and no `n > 1`.
Details: [Performance and limits](/docs/performance/).
</Note>
