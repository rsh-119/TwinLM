# Usage and savings

Every request, including errors, blocked requests, cache hits and client disconnects, produces one usage record:
request ID, key, project, provider, model, deployment, tokens, cost, latency, time to first token, status,
whether it fell back and whether it was a cache hit. **Prompts and replies are never stored in usage records.**

## Prices

Cost is computed from the prices you configure, in USD per million tokens, keyed by `provider/model`:

```toml
[pricing."gemini/gemini-flash-latest"]
input_per_million = 0.30
output_per_million = 2.50

[pricing."groq/openai/gpt-oss-20b"]
input_per_million = 0.075
output_per_million = 0.30
```

<Note title="Verify prices">
The shipped prices are examples. Check them against each provider's current price list, and reconcile with your
invoices monthly. A model without a price entry is recorded with cost **unknown (null), never 0**, so missing prices
can never make a report look cheaper than it is.
</Note>

Costs are estimates: configured price × the token counts the provider reported, summed over every billed call
(including structured-output repair calls). Gemini's thinking tokens count as output.

## Usage report

```bash
curl "http://localhost:8000/admin/usage?hours=24&group_by=project" -H "Authorization: Bearer $ADMIN_TOKEN"
```

| Query parameter | Values |
| --- | --- |
| `hours` | Look-back window, default `24`, max `2160` (90 days) |
| `group_by` | `provider` (default), `model`, `deployment`, `project`, `api_key_id` |

```json
{
  "since": "2026-10-13T09:00:00+00:00",
  "group_by": "project",
  "total": {
    "requests": 1240, "errors": 3, "fallbacks": 12,
    "cache_hits": 410, "cache_hit_rate": 0.3306,
    "total_tokens": 812400, "cost_usd": 0.41,
    "unpriced_requests": 0, "cost_complete": true
  },
  "groups": [
    {"project": "support", "requests": 900, "errors": 1, "fallbacks": 9, "cache_hits": 400,
     "prompt_tokens": 512000, "completion_tokens": 140000, "total_tokens": 652000,
     "cost_usd": 0.29, "unpriced_requests": 0, "avg_latency_ms": 640.2, "avg_ttft_ms": 310.5}
  ]
}
```

*(Illustrative numbers.)* Grouped by `provider` or `model`, each group also has `p50_latency_ms` and
`p95_latency_ms`. Provider token totals exclude cache hits. When `cost_complete` is `false`, some requests had an
unknown price or unreported usage; `unpriced_requests` says how many.

## Savings report

The savings report answers "what would this traffic have cost without TwinLM?". Pick a **baseline**: the model
you would otherwise send everything to. It needs a price entry.

```toml
[pricing."openai/gpt-4o"]
input_per_million = 2.50
output_per_million = 10.00

[savings]
baseline = "openai/gpt-4o"
```

```bash
curl "http://localhost:8000/admin/savings?hours=720&group_by=project" -H "Authorization: Bearer $ADMIN_TOKEN"
```

| Query parameter | Values |
| --- | --- |
| `hours` | Default `720` (30 days), max `8784` (366 days) |
| `group_by` | `project` (default), `api_key_id`, `provider`, `deployment` |

Per group and in total, it returns:

| Field | Meaning |
| --- | --- |
| `requests`, `measured_requests` | All requests, and those whose tokens and price are known |
| `cache_hits` | Requests answered from cache |
| `actual_cost_usd` | What the measured requests actually cost |
| `baseline_cost_usd` | The same measured tokens priced at the baseline model |
| `savings_usd`, `savings_pct` | Baseline minus actual, and as a percentage of baseline |
| `cache_avoided_usd` | What the cache hits would have cost on the model that originally answered |
| `complete` | `true` when every request was measured |

The savings come from two places: cheaper models (routing) and requests that never reached a provider (cache).
Without a `[savings] baseline`, the endpoint returns 404.

<Note title="How to read it honestly">
Token counts come from the models that actually served the requests; a different model would tokenise the same
text slightly differently. Requests with unknown tokens or price are left out, and the report says so with
`complete: false`. Treat it as a good estimate, not an invoice.
</Note>

## In Prometheus

The same data is exported as metrics: `llm_tokens_total`, `llm_cost_usd_total`, `llm_cache_hits_total`,
`llm_fallback_total` and more. See [Monitoring](/docs/monitoring/).
