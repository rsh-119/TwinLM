# Remediation status after the architecture audit

> **Historical (pre-14 October 2026 architecture work).** Several open items below are now implemented: user-bound keys, versioned migrations, compatibility errors, Compose profiles, TLS ingress, alerts, dependency/image locking. The current state is [ARCHITECTURE.md](ARCHITECTURE.md); procedures are in [OPERATIONS.md](OPERATIONS.md).

The `audit/` reports are an as-of snapshot of the original codebase. This
document tracks subsequent local changes. Passing the offline test suite does
not establish readiness for an unrestricted public deployment.

## Implemented locally

- External JSON Schema references are rejected through an offline registry;
  schema size and complexity are bounded. Returned structured JSON is
  revalidated after output guardrails.
- Request IDs are generated by the server; a client correlation ID is echoed
  separately. Input checks cover stored memories, history, tools and request
  metadata before provider calls.
- Stateful exchanges commit both messages atomically and reject stale
  conversation versions. Summary updates also check the version.
- Stream interruptions, guardrail findings and persistence failures now carry
  an explicit incomplete terminal outcome and failed usage status.
- Usage writes enter a local SQLite outbox, retry after database failures,
  replay after restart, and retain malformed rows in a deadletter table.
  Pending and deadletter counts are exposed as metrics. Compose persists the
  outbox on `gateway-data`.
- Startup validates gateway configuration and initializes services before
  readiness. Provider 4xx and credential errors have typed, sanitized HTTP
  mappings. Additive schema setup is serialized and repeatable.
- Message and memory history use bounded SQL queries and cursor pages.
  Summary and memory context input are bounded; summaries include the previous
  summary. Repair costs use the actual
  provider for each call; summary calls are logged separately.
- Request bodies, concurrent requests, stream duration, and streamed text are
  bounded. The test console has a fixed configured gateway target and no
  inherited admin credential.

## Operating contract and open launch gates

The daily budget remains **advisory**. It checks settled plus local pending
usage, but cannot reserve worst-case spend for concurrent requests or account
for unknown prices/usage. Hard enforcement requires verified price data,
output caps for every supported model, an atomic reservation/settlement
contract, and a decision about whether unknown-cost models are rejected.
The in-process RPM/TPM limits, breakers and cache are single-instance only.

The Streamlit console and built-in web UI have no user login. Compose binds
ports to loopback by default; shared or public access requires a separate
authenticated ingress and TLS. The gateway's admin token must remain private.
Project isolation exists, while callers within one project can choose any
`user_id` in that project.

Streaming text is checked after it has already been sent. A guardrail finding
now marks the stream incomplete and prevents stateful persistence, but cannot
recall bytes delivered to a client. If output blocking is required for
sensitive data, use non-streaming chat until a buffered stream policy is
designed and verified.

Off-host encrypted backups, restore drills, retention/deletion policy,
credential rotation, TLS ingress, verified provider prices, dependency/image
locking and scans, and production-like load tests remain launch
work. The isolated PostgreSQL exchange/outbox integration test passes locally,
but it is not a production migration or restore drill. These remaining tasks
require a target hosting and data-retention contract. No live
provider, public endpoint, backup destination, or production database was
modified during this remediation.

## Local verification

The current offline suite passed **227 tests** with one PostgreSQL case
skipped when `TEST_DATABASE_URL` is absent. That case also passed against
a disposable local PostgreSQL 16 container. `pip check` and
`docker compose --env-file .env.example config --quiet` passed. Rerun these
for the final release candidate. Watch `llm_usage_backlog_rows`,
`llm_usage_deadletter_rows`, `llm_usage_write_failures_total`, and failed
stream request status. A deadletter row must be investigated and reconciled
with the main ledger before relying on cost totals.
